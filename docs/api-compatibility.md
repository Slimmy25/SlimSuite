# Client API decisions

The supplied `addon_docs(3).md` and the installed client's embedded addon Lua were inspected on November 14, 2026. No new game CVar or guessed API signature is required by these changes.

- **Confirmed cache opens:** the documented `AZS_RUN.ck` field counts opened caches. The tracker establishes a baseline per `AZS_ZONE.run` (or the meter context's `runId`), plays once when the counter increases, and resets its baseline on a new run or counter decrease. It does not infer opens from `AZS_CHESTS` removals. A missing counter produces no sound.
- **Enemy DoTs:** `AZS_GetDebuffs(unitId)` documents boss/guardian debuffs with `icon`, `remaining`, `duration`, `stacks` and other fields. Native and modern attachments use that data and documented world anchors/projection. The native attachment draws no replacement health/name body. Ordinary enemy DoT timings are not invented when the API does not supply them. The feature is optional.
- **Shields:** `AZS_RUN.sh` is the local hero's aggregate absorb value. The documented party table contains meter data, not teammate shield totals. `SS.AbsorbAmount` therefore returns unknown for teammates unless the client provides `UnitGetTotalAbsorbs`. It does not label damage/healing totals as shields or assign an aggregate shield to an individual buff.
- **Compiler:** `tools/check-lua50.py` builds the upstream Lua 5.0.3 compiler from its SHA-256-pinned source archive and parses each untouched production module in the manifest. Behavioral scenarios still use the explicitly mocked Lua 5.3 client; these are separate checks.
- **No off-screen renderer established:** no documented headless/off-screen UI test mode was found in the available client material. No hidden gameplay session, desktop input injection or live-game rendering claim is made. The user's request to avoid desktop interaction takes priority over completing visible-client checks.

Live verification remains needed for physical screen edges, native artwork/masks, translated text fit, real combat DoT alignment and other-addon interactions.

- **Live stats:** the Stats element reads the documented `AZS_STATS` character-pane values directly; `AZS_RUN.hp/hpm/sh` supplies current HP, maximum HP and total shield. It does not add `g*` gear values or guessed racial/buff multipliers to those totals. `AZS_SPELLS` documents the racial as its final entry; `AZS_BUFFS` supplies spell IDs and remaining time. Unavailable values are shown as unknown rather than invented. No per-buff stat attribution is exposed by this contract.

- **Stats split mode:** Default is the observed pre-run (`ready`) total, already including starting racial/gear/talent effects. Bonus is the current total minus that observed value, so later purchases and temporary changes are included exactly once. A run identity mismatch or missing baseline falls back to the current total. The documented gear-only `g*` contributions are not presented as a complete item/spell/buff breakdown.
- **Bounds on legacy clients:** custom renderers reserve glyph/icon dimensions and keep tiered combat text inside the box edges. The shared bounds pass suppresses regions outside the same geometry used by green handles, releases suppression after enlargement or native restoration, and uses native child clipping only when available. Real-client rendering still needs verification.

- **Native world damage:** the installed client’s own options Lua and CVar registry confirm `CombatDamage` as the toggle for numbers over creatures. Slim Suite stores/restores its original value; no undocumented damage-number CVar is used.
- **Pregame positions:** `AZS_GetUpcomingBosses()` and `AZS_SCHEDULE` expose names and times, not future spawn coordinates. Dim previews use only existing catalog positions or real cache/lair entries. Minimap/compass entries match published run/map/space identities when available. Unknown spawn locations remain unavailable.
- **Selection-screen edges:** `AZS_SetOnTopOfScreens` supports above-card rendering and input, including GameTooltip. It does not expose the card rectangles themselves. Build/Stats therefore use viewport-edge gutters during `choosing`, restore their prior anchors afterward, and never claim to follow a private renderer card rectangle.
- **Build descriptions and cooldowns:** exact spell hyperlinks and real spellbook matches supply native descriptions. The installed legacy client lacks `GetSpellBookItemInfo`; matching descriptor names/ranks to `GetSpellName` provides its fallback. Cooldowns read the existing AZS_SPELLS entries (racial last); ready previews do not decrement an invented timer.

- **Native guardian flag:** when the custom map/POIs are in use, the edge-clamped native flag is suppressed and its flagged lair is drawn at the actual reported coordinate, disappearing out of range. The original native flag setting is retained for vanilla/logout restoration. Third-party addon icons remain owned by their own addons.

- **Moving compass/map targets:** a small alive-boss/final-boss/guardian catalog query is shared once per UI frame. It rereads current world positions even when catalog membership/ID has not changed. Camera projection pixels are never misused as world coordinates. Static lairs and chests retain their real locations.
- **Selection-only items:** the native card footer has no published frame rectangle. The supplied 2560×1440 screenshot is normalized to a 1280×720 footer layout, with 30-unit icons and 5-unit spacing; placement follows viewport scaling. This is a screenshot-based layout template, not a native-geometry API claim. This implementation is retained but currently disabled by SS.CHOICE_ITEMS_DEFERRED. When deliberately re-enabled for testing, the custom spell row is hidden while native spells are present and items are temporarily shown beneath it without writing profile preferences.

- **Encounter targeting:** each native enemy-selection request waits for `AZSTGT` before accepting an exact spawn ID or requesting the next candidate. Duplicate candidates, bounded attempts and response timeouts stop cycling. Restoration is also verified against the original spawn ID; matching a name alone is insufficient.
- **Ordinary Explosive Orbs:** living world anchors discover orb spawn IDs and marker handles even when they are absent from `AZS_UNITS`. Their health comes only from an exact-ID `AZS_UNITS` or current `AZS_TARGET` entry. The anchor API exposes no HP, so otherwise the encounter row explicitly shows “Health unavailable” and no health fraction is invented. Discovery currently recognizes the supplied English creature name; localized creature identifiers are not published by this API.
- **Demo editor isolation:** editing predicates return false during Demo. Build-row refreshes cannot reopen green handles; checks inspect existing handles without calling the handle factory, including after repeated refresh/timer updates.

- **Encounter kill sounds:** the native banner callback, raw documented `AZSBANNER` message and banner ring share ID deduplication. Confirmed dead boss/final-boss/guardian anchors and increases in documented `AZS_RUN.bk/gk` provide independent fallbacks. Confirmation channels are matched one-to-one within three seconds by enemy type/name, so several same-name deaths still each sound once. Initial corpse/counter snapshots are seeded silently. Low HP and ordinary disappearance do not trigger audio. Standard MP3 assets use the pinned mix target; Hitmarker retains its explicit pre-limiter gain exception; measured output and source hashes are recorded in `audio-normalization.json`.

- **Adaptive combat highlights:** learning uses only incoming combat-event amounts, critical flags and documented source keys/spell IDs. It blends minute summaries, retains at most 64 sources, drops inactive sources after three minutes and resets on a changed run ID. It changes presentation only; all unfeatured hits still enter the bounded normal log. Demo samples bypass real learning. Animation runs once per rendered frame, not at an artificial game frame-rate setting.
- **Sound selection:** each event group has one active choice, including Off. Existing sound flags remain readable; conflicting older boss flags select hitmarker, then whip, then Gotcha deterministically until a new choice clears them. Speaker previews work independently of which sound is enabled. The shortened chest asset retains only the ending phrase, with small endpoint fades.

- **Match audio:** `AZS_GetPhase()` (or documented `AZS_RUN.ph`) distinguishes a recoverable co-op death from the party-wide `dead` phase; `AZS_GetRunSummary()`/`AZS_END.result` confirms defeat, victory or leaving. Pending ordinary death sounds wait 0.75 seconds for terminal state delivery and are discarded on defeat. Ready → Playing plays the optional start sample once. Audio uses `PlaySoundFile`, the same path as previews; Slim Suite never changes the native music toggle and does not call `PlayMusic` for these samples. Live native channel/volume behavior remains unverified.

- **Teammate/victory choices:** teammate deaths can inherit the player choice or use an independent sound, including Roblox, even if player death audio is Off. The documented party-wide victory phase triggers the optional GTA sample once per win, with no replay on loading a historical end screen.
- **Audio leveling:** build-time ffmpeg processing targets -12 LUFS (1.5 dB above the original Whip Crack) with endpoint fades and peak limiting. Output checks use decoded MP3 true peaks, not just pre-encode sample peaks. Effects under 400 ms are repeated only for measurement/normalization and trimmed back to their original duration. The current inventory has 19 measured assets. The pinned target and decoded peak limits are checked by tools/check-audio.py. Hitmarker has an explicit +6.02 dB pre-limiter exception; Cena has a -3 dB bass adjustment around 120 Hz. Audible mix testing is deferred by the owner. Runtime playback requires no external executable.


- **Normal combat text preservation:** highlights can occupy at most roughly 65% of the box rows, leaving at least one normal row. A one-row box demotes highlights to ordinary text. Weak/non-featured crits use ordinary white styling and no critical suffix, while their true critical flag remains available to the learner. Both per-source and player-wide learned damage baselines govern highlighting.

- **Combat insertion continuity:** a runtime cursor shared by ordinary and featured hits advances once per accepted line. Expiration and hiding do not reset it, and surviving rows are never repacked. Reusing a row clears its prior line first. The cursor wraps into current bounds after a resize; no saved layout/profile data is modified.

- **Start-song timing:** there is one optional start-song selector, triggered only by `ready` → `playing` (first movement). The unsupported early-load option is removed; saved enabled early-load choices migrate to the start-song setting.

- **Module hub:** category switches operate only on SlimSuite. Chat/sound masters gate their behavior without erasing choices. Gameplay/Misc preserve owned settings while paused. User Interface restores native HUD modes while retaining a category snapshot, and profile export/autosave reads retained preferences. Imports and login reapply disabled-module restrictions. Diagnostics and third-party addon management are no longer exposed; no `EnableAddOn`/`DisableAddOn` calls remain in the settings window.

- **Meter origin tags:** documented `Source.kind`, source-key families and explicit `originSourceKeys` identify Talent/Gear contributions. Unknown origin stays unlabeled rather than guessed from a spell name. A separate tag region reserves space beside the spell name.
- **Luck display:** optional legendary-only estimates use the supplied rarity-weight chart and live total `AZS_STATS.luck`, plus the model's capped level bonus and amulet source bonus. It is a per-card model estimate. See `luck-model.md` for reviewed creator-note versions and exclusions. The released display uses percentages, a stable graph and measured starting/current improvement, without investment/status phrases; the green setup handle and resize grip remain available even when the optional live display is off.
- **Treasure context limitation:** the published phase API reports both spell and jewelry choices as `choosing`. It exposes neither the current reward category nor native footer rectangles. The retained automatic item overlay cannot reliably switch to spells for treasure without a new creator API or an explicit manual context selector. The owner has deferred this work and disabled the item overlay without deleting it.

- **Choice clock corroboration:** when `AZS_GetRunTime()` is readable, opening requires `choosing` plus a clock that stays unchanged for at least 0.25 seconds. Returning to `playing` waits for clock movement; a one-second safety timeout prevents a stuck overlay on broken clock delivery. Other phases and explicit overlay/editor settings close it immediately. Missing clocks retain phase-only compatibility. This confirms card-screen activity, not treasure versus level-up type.

### Sound preview transport
The inspected native client exposes PlaySoundFile, PlayMusic and StopMusic, but no StopSound, PauseSound or IsSoundPlaying. A music-channel workaround would take over native music and depend on music settings; it is not used. On clients returning sound handles with StopSound, previews stop the previous handle before starting a replacement. The active button uses pause-style bars, but the action stops rather than resumes. A failed stop retains the active preview and queues the request. On the inspected legacy client the latest requested preview waits for the tracked duration to end; muted bars indicate a queued clip. This is a non-overlapping queue, not an implementation of true pause. No global audio setting is changed. Halo Game Over remains exclusive to confirmed final defeat.
