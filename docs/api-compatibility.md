# Client API decisions

The supplied `addon_docs(3).md` and the installed client's embedded addon Lua were inspected on November 14, 2026. No new game CVar or guessed API signature is required by these changes.

- **Confirmed cache opens:** the documented `AZS_RUN.ck` field counts opened caches. The tracker establishes a baseline per `AZS_ZONE.run` (or the meter context's `runId`), plays once when the counter increases, and resets its baseline on a new run or counter decrease. It does not infer opens from `AZS_CHESTS` removals. A missing counter produces no sound.
- **Enemy DoTs:** `AZS_GetDebuffs(unitId)` documents boss/guardian debuffs with `icon`, `remaining`, `duration`, `stacks` and other fields. Native and modern attachments use that data and documented world anchors/projection. The native attachment draws no replacement health/name body. Ordinary enemy DoT timings are not invented when the API does not supply them. The feature is optional.
- **Shields:** `AZS_RUN.sh` is the local hero's aggregate absorb value. The documented party table contains meter data, not teammate shield totals. `SS.AbsorbAmount` therefore returns unknown for teammates unless the client provides `UnitGetTotalAbsorbs`. It does not label damage/healing totals as shields or assign an aggregate shield to an individual buff.
- **Compiler:** `tools/check-lua50.py` builds the upstream Lua 5.0.3 compiler from its SHA-256-pinned source archive and parses each untouched production module in the manifest. Behavioral scenarios still use the explicitly mocked Lua 5.3 client; these are separate checks.
- **No off-screen renderer established:** no documented headless/off-screen UI test mode was found in the available client material. No hidden gameplay session, desktop input injection or live-game rendering claim is made. The user's request to avoid desktop interaction takes priority over completing visible-client checks.

Live verification remains needed for physical screen edges, native artwork/masks, translated text fit, real combat DoT alignment and other-addon interactions.

- **Live stats:** the Stats element reads the documented `AZS_STATS` character-pane values directly; `AZS_RUN.hp/hpm/sh` supplies current HP, maximum HP and total shield. It does not add `g*` gear values or guessed racial/buff multipliers to those totals. `AZS_SPELLS` documents the racial as its final entry; `AZS_BUFFS` supplies spell IDs and remaining time. Unavailable values are shown as unknown rather than invented. No per-buff stat attribution is exposed by this contract.

- **Stats split mode:** Default is the observed pre-run (`ready`) total, already including starting racial/gear/talent effects. Bonus is the current total minus that observed value, so later purchases and temporary changes are included exactly once. A run identity mismatch or missing baseline falls back to the current total. The documented gear-only `g*` contributions are not presented as a complete item/spell/buff breakdown.
- **Bounds on legacy clients:** custom renderers reserve glyph/icon dimensions and expire combat popups at the box edges. The shared bounds pass suppresses regions outside the same geometry used by green handles, releases suppression after enlargement or native restoration, and uses native child clipping only when available. Real-client rendering still needs verification.

- **Native world damage:** the installed client’s own options Lua and CVar registry confirm `CombatDamage` as the toggle for numbers over creatures. Slim Suite stores/restores its original value; no undocumented damage-number CVar is used.
- **Pregame positions:** `AZS_GetUpcomingBosses()` and `AZS_SCHEDULE` expose names and times, not future spawn coordinates. Dim previews use only existing catalog positions or real cache/lair entries. Minimap/compass entries match published run/map/space identities when available. Unknown spawn locations remain unavailable.
- **Selection-screen edges:** `AZS_SetOnTopOfScreens` supports above-card rendering and input, including GameTooltip. It does not expose the card rectangles themselves. Build/Stats therefore use viewport-edge gutters during `choosing`, restore their prior anchors afterward, and never claim to follow a private renderer card rectangle.
- **Build descriptions and cooldowns:** exact spell hyperlinks and real spellbook matches supply native descriptions. The installed legacy client lacks `GetSpellBookItemInfo`; matching descriptor names/ranks to `GetSpellName` provides its fallback. Cooldowns read the existing AZS_SPELLS entries (racial last); ready previews do not decrement an invented timer.

- **Native guardian flag:** when the custom map/POIs are in use, the edge-clamped native flag is suppressed and its flagged lair is drawn at the actual reported coordinate, disappearing out of range. The original native flag setting is retained for vanilla/logout restoration. Third-party addon icons remain owned by their own addons.
